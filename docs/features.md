# Features — the flat table

> One row per feature, for dispatching work to agents in separate sessions. **Status**: built · partial · planned · later (out of the first real version by decision) · dropped · owner (only the owner can do it). **Touches** names the shared files a change needs (`schema`, `nav`, `package.json`; `i18n` no longer counts — D62) — two builders may not hold PRs on the same shared file at once, and never two migrations at once. **Size**: S < half a day · M a day · L several. Source of truth for status: `specs/<module>/tasks.md` ticks and [[feature-inventory]] §3 status lines; **every feature PR updates its row**.

Dispatch rule: pick a row with status planned, give the builder its ID, the module, and "never touch any other module's folder"; two builders at a time only on rows with different modules and no shared file in common.
