# Lessons from the build — what to improve, what to do differently

> Written at the end of the 2026-10-20 → 21 build (51 PRs, every module's first slice) for whoever continues. Each item is a finding **and** the action; tick them off or move them into [[roadmap]] when picked up. Not a backlog of features — those are in the roadmap.

## Process

- [ ] **e2e flakiness is the recurring cost** (three fixes in one day: a journey reading another's data, a row click landing on a link after column widths, a journey running out of its total budget on a loaded runner). Rules that hold: every journey **owns its data** (uploads / creates what it reads — `document-review.spec.ts` is the model); open an entity by **deep link** (`?open=`, `?q=`, `/documents/<id>`) rather than by clicking the n-th row; give long journeys `test.setTimeout(240_000)` up front; two workers stay — if a fourth flake appears, measure one worker (+2 min) before fixing one more test.
- [ ] **CI logs are not reachable from a cloud session** (the blob host is behind the proxy); the check-run **annotations** are. Keep the Playwright failure summary in an annotation (it is), and consider annotating `test-results/*/error-context.md`'s first lines too.
- [x] **A cloud session rebuilds its environment from nothing** (Postgres cluster, Azurite, env vars, the prod build with a `next/font` stub because Google Fonts is unreachable). Two scripts moved into `scripts/` (`merge-when-green.sh`, `reset-e2e-data.sh`); the rest is still per-session. Action: `scripts/dev-env.md` (or a `scripts/dev-env.sh`) describing the exact steps — the test DB URLs and roles, `apply-migrations` by psql when the Prisma engine is missing, the seed with the migration role, the font stub, `next start` on :3000 — so the next session does not rediscover them. Two more found in F48: `prisma generate` needs `PRISMA_SCHEMA_ENGINE_BINARY` pointed at any stub executable (the engine download is blocked, generate does not use it), and the local test Postgres must run in **UTC** like CI (`ALTER SYSTEM SET timezone = 'UTC'`) — otherwise the inbox and partner date-filter tests fail for nothing. Done (F49): `scripts/dev-env.sh` + `scripts/dev-env.md` — both of those included, plus Playwright's Chromium (`cdn.playwright.dev` is blocked; the image's `/opt/pw-browsers` build is symlinked) and a Turbopack-compatible font mock (plain data, generated).
- [ ] **Run `biome check --write .` before every commit**: four "chore: format" commits in a day. `.husky/` exists — add a pre-commit that formats the staged files.
- [ ] **Screenshots came from a hand-written script** that re-did the e2e's steps. Put every new page in `e2e/screenshots.spec.ts` (it runs on `main` and uploads the artifact) and take the PR's pictures from there.
- [ ] **Spec-kit, the house way, is right-sized**: `spec.md` for the owner's read, `plan.md` + `tasks.md` for the agent; no `research.md` / `data-model.md` / `quickstart.md`. The owner's one gate (reading the spec) caught nothing this time — keep it anyway; it is cheap and it is where a wrong assumption would be caught.
- [ ] **The merge watcher had a race** (#47 merged on the previous head's green while a push landed). Fixed in #49 (waits for the full run set, re-reads the head). Lesson: a script that merges needs the same scrutiny as code.

- [ ] **`docs/features.md` is the dispatch table**: every feature PR updates its row (status, what is left) — a stale row sends an agent to build what exists.

## Code

- [ ] **Module-load cycles through the linking registry**: `modules/linking/index.ts` eagerly imports `./linkables`, which imports every module — so any module importing `@/modules/linking` is in a cycle at load time; `supplier-invoices` could not use a Zod schema from `expenses` at the top level (declared twice instead). Action: register linkables lazily from the composition root (`src/instrumentation.ts` already wires `contracts.setRateUsage`) and drop the eager import.
- [ ] **A client barrel cycle** `expenses/ui ↔ documents/ui` (settlements-table ↔ make-it-section) works at render time but is fragile. Action: either the review *page* composes `MakeItSection` (pages may import both), or `settlements-table` takes the download action as a prop. Add a guard rule against `ui.ts ↔ ui.ts` cycles.
- [ ] **Reads of `link` outside the linking module** (documents' `unlinkedIds`, the inbox query, the upload card's *became*) are allowed (only writes are reserved) but spread knowledge of the table. Action: a read API `linking.createdFromTargets(tx, documentIds)` / `justifiedIds` and use it.
- [x] **The inbox read model loads every non-generated document per request** (cap 20 000, in-memory state / twins / counts). Right for one company; say so in `docs/document-inbox.md` and revisit if a tenant passes a few thousand documents. Said there (part 2).
- [ ] **`storage.test.ts` › *generateDownloadUrl sanitizes filename* fails when Azurite runs** (`.._.._evil_path.pdf` keeps the `..`): CI's unit job has no Azurite, so the suite is skipped there and the failure never shows. Harmless for a download name, but either sanitise the dots or fix the expectation — and give the unit job Azurite so the storage tests run (found 2026-10-21, inbox part 2).
- [ ] **A date filter depends on the Postgres session time zone**: `partners/queries.test.ts` › *dates by year / month / range on createdAt* (and the inbox date filters, F48) fail (year filter → 0 rows) on a cluster in `Europe/Budapest` at 01:00 local, passes with the database in UTC. CI's container and the image run UTC, so it never shows — but the homelab or a laptop Postgres in local time would. Action: decide what "a date" means for filters (UTC, or Europe/Stockholm for the company) and make the date-filter SQL say it explicitly (`AT TIME ZONE`) instead of inheriting the session; `dev-env.sh` pins the cloud cluster to UTC meanwhile (found 2026-10-22, F49).
- [x] **`.toNumber()` lint rule and Sentry request context** — done in F48 (Biome GritQL plugin; context on the event, not on a shared scope).

**Brief for the fresh agent doing the real audit** (one session, read-only, report as a checklist like this file): for each module, read the service and the queries once; look for (1) a rule written twice, (2) a status or amount stored where it should be derived, (3) a component over 400 lines doing two jobs, (4) a cast that hides a missing type, (5) a cross-module read that bypasses the other module's `index.ts`, (6) a test that tests the mock rather than the rule. Do not fix while auditing; do not propose a framework; propose the smallest PR per finding and the order.

## Code — the audit (2026-10-22, read-only, the brief above)

Every module's services and `queries.ts` read once (plus their tests for check 6, the components over 400 lines for check 3). Each box is **one PR**, in the order to do them; *(cN)* = the brief's check, `path:line` = where it was seen (verified by reading the lines). Nothing was fixed. Clean: numbering on all six checks; no module **writes** another module's table (writes to `link` are linking's only); no raw SQL on another module's table; bank-row and journal money facts are locked by triggers and never updated.

```
1–8   wrong figures today (tax return, receivables, paid status, SEK bases)   → fix first, a test each
9–21  rules that drift or block the owner (medium)
22–26 read APIs instead of tx.<other module's model> (c5) — one PR per owner module
27–32 hygiene: one helper instead of N, JSON columns parsed, enums, tests, components
```

### Wrong figures (high)

- [ ] **1 · Swiss VAT return recomputes VAT from the lines, ignoring the header discount** *(c1)*: it sums the stored line `netAmount` / `vatAmount` (before the discount, rounded per line) instead of the invoice's `vatByRate` (discounted, rounded per rate) — `exports/queries.ts:96-101` vs `invoices/totals.ts:127-140`. Any discounted invoice inflates the 30x bases and tax and differs from the printed invoice. Fix: build the return's rate rows from `inv.vatByRate × factor`. Same PR: `inv.netAmount || "1"` never falls back (`"0.00"` is truthy → divide by zero, NaN lines) `exports/queries.ts:96`; `declaredOn` filters by period only, not registration `exports/queries.ts:197-200`.
- [ ] **2 · `declare()` freezes whatever lines the browser sends** *(c2)* — `exports/declarations.ts:43-56,196`. A stale page or a hand-made request files figures the server never computed. Fix: `declare()` calls `swissVatReturn` and stores `computed.lines`; drop `lines` from the input; `ref: z.enum(SWISS_VAT_REFS)`.
- [ ] **3 · A credit note goes "overdue" the day after issue and counts as a receivable** — `invoices/derive.ts:24-46` gives credit notes the invoice path, and `invoices.ts:926` sets `dueDate = issueDate`; `dashboard/overview.ts:104-108` then adds its total to receivables (the credited invoice is already reduced) and to the overdue count. Fix: `deriveState` — a credit note is never overdue / never "open"; the dashboard sums `type = invoice` only. Same PR: the receivables hint counts quotes it does not sum (`overview.ts:118`).
- [ ] **4 · Expenses and supplier invoices store the bank payment on the entity, but the generic link path does not** *(c2)*: `paid_amount` / `paid_currency` / base are written only by the panels' *attach* (`expenses/expenses.ts:516`, `supplier-invoices/payments.ts:209-218`). A suggestion applied from the linking inbox (`linking/suggestions.ts:251`) creates the `justifies` link without them → the expense stays `awaiting_link` forever (`expenses/status.ts:32`) and is locked; removing an attach-made link through `removeLinkAction` leaves the paid amount and bank base behind (both modules). Smallest fix: the two linkables refuse generic `justifies` create/remove and the inbox opens the entity's attach instead; the real fix (derive paid from the link, the bank base as a new fact) is decision D1.
- [ ] **5 · Supplier invoice: any money-field edit replaces a manual rate by ECB** — `supplier-invoices/supplier-invoices.ts:532,570` calls `baseFor(…, v.rate)` with `v.rate` undefined when only `invoiceNumber`, `partnerId` or `dueDate` changed. Fix: keep the stored rate/base unless currency, date, total or rate changed. Same PR: changing `invoiceDate` resets the due date to +30, ignoring the partner's terms and a typed due date (`:562-566`) — re-default only when `dueDateDefaulted`.
- [ ] **6 · Supplier invoice "allocated" has two definitions** *(c1)*: the list/detail/KPIs count `justifies` from `bank_transaction` only (`supplier-invoices/queries.ts:121-127`), payments count every `justifies` (`payments.ts:47-58`) — and linking allows `journal_entry → supplier_invoice` (`linking/kinds.ts:9`). Fix: one sum (via the linking batch query of PR 22), one `fromType` rule.
- [ ] **7 · Nearest ECB rate has no distance cap and no tie-break** — `rates/ecb-rates.ts:243` (`ORDER BY ABS(date - $2)` `LIMIT 1`): a sync gap of weeks silently becomes an immutable rate; a Sunday takes Monday's rate; a mid-week tie is arbitrary. Fix: previous rate first (`, date ASC`), cap ~4 days, else null → "run the ECB sync".
- [ ] **8 · Invoice `subtotalBase + vatBase ≠ totalBase` with a discount** — `invoices/invoices.ts:658-661` converts the subtotal before the discount, the total after. Fix: store the converted net; add the discounted case to the test.

## Working with the agent — for the owner

- The agent is cheapest when it can **read small and run little**: targeted `grep` / `sed -n` reads, one unit test file at a time, the full suite once before the PR, the e2e for the touched journeys only, the local `next start` kept running across tasks.
