# Journal — the categorised ledger of financial facts

Module `src/modules/journal` · schema `prisma/schema/journal.prisma` · migration `20261021100000_add_banking_import_and_journal` · spec `specs/journal/spec.md` · decisions D1, D2, D3. Part 1: model, service, queries, linkable. Part 2: the `/journal` page and the categorise form shared with the banking workbench.

> One entry per bank transaction (created by the [[banking]] import) or typed by hand. The money facts — amount, currency, SEK base, rate, rate source, date, description — are written once; the owner's facts — BAS category, partner, note, *no document needed* — change freely and never get overwritten by a rule. Not a ledger: no debit / credit, no posting, no fiscal year. The accountant books; the journal is what she and the owner read.

## Model

```
journal_entries   source_type ∈ bank_transaction | manual · source_id? (the transaction id, validated UUID; unique per source)
                  entry_date · description · counterparty_key?        (copied at import — the journal never reads banking)
                  amount (signed) · currency · amount_base (SEK, 2 dp) · rate (6 dp) · rate_source ∈ same_currency | ecb_daily | ecb_nearest | manual · rate_date?
                  bank_implicit_rate? (not read since T005 — the DTO's `bankImplicitRate` is derived from the `transfer` link)
                  bas_code? (bas_categories.code, 3 digits) · partner_id? · note? · no_document_needed
                  categorised_by ∈ manual | rule | null · rule_id?   (the enum still has `partner_default`, never written — audit 32, goes with F67's schema PR)
```

Trigger `journal_entries_lock_money`: amount, currency, amount_base, rate, rate_source, rate_date, entry_date, source, description, counterparty_key never change; `bank_implicit_rate` only NULL → value. `block_delete_when_linked('journal_entry')`. RLS.

## Service — `journal.ts`

- `baseAmount(amount, rate)` (pure): `round(amount × rate, 2)` half-up, never `-0`; property-tested.
- `resolveRate(tx, date, currency)` / internal `baseFor`: SEK → 1 `same_currency`; else `rates.rateToBase` (ECB of the date, `ecb_nearest` with the actual `rate_date` when the day has none); **refused** when no rate exists — the banking import pre-checks every date before writing.
- `createBankEntries(tx, caller, audit, rows[])`: batch, all or nothing, audited; `createManualEntry` (ECB of the date, or a typed rate → `manual`; a typed SEK rate must equal 1 as a number — `1.000000` is accepted, audit 32).
- `categorise(tx, caller, audit, id, facts, {by, ruleId})`: by hand → written as given, `categorised_by = manual`, `rule_id` cleared; by a rule → category only when none, partner only when none, flag OR-ed, and an entry categorised by hand is returned unchanged. BAS code through `settings.getBasCategory`, partner through `partners.getPartner`.
- `withImplicitRates(tx, entries)` (`implicit-rate.ts`, T005): a bank entry whose transaction sits in a `transfer` link with a base-currency transaction gets the pair's |base| ÷ |foreign| (6 dp half-up) as `bankImplicitRate` — derived on every read (`getJournalEntry`, `entriesForSources`, the ledger, `categorise`'s result), so an unpairing takes it away and a re-pair brings the new pair's rate; never replaces `rate`. It loads `@/modules/linking` on first use (a top-level import closes a load cycle through banking). `setBankImplicitRate` (once) still exists but nothing reaches it: banking's accept sees the derived rate and skips it; it goes with the column (T010).
- `deleteBySource` (the banking import's delete), `deleteManualEntry` (bank entries are never deleted by hand; linked entries refused by the trigger).

## Reads — `queries.ts`

`entriesForSources(tx, type, ids)` → `Map<sourceId, entry>` (the banking workbench joins on it) · `getJournalEntry` · `JOURNAL_COLUMNS` + `listJournalEntries` / `distinctJournalValues` / `journalDateHierarchy` — two-step list (stored filters in SQL, `partnerName` / `basLabel` joined, derived filters / search / sort / page in memory through `kernel/list-query/memory`), sums of `amount_base` on the filtered set. Each row carries `accountAlias` (T006 — a bank entry's account label through banking's read API `accountAliasesFor(tx, transactionIds)`, loaded on first use like linking; searchable) and `linksState` (T004, `links-state.ts`): `no_document` (the flag, or a transfer leg — D44), `justified` (Σ allocations ≥ |amount| − the settlement tolerance), `partly` (Σ > 0), else `none` — a bank entry reads its transaction's allocations (the banking workbench's state, same rule), a manual entry its own; three grouped queries through linking's read API (`allocatedFrom`, `linksTouching` with `kinds`). Derived, filtered in memory, never typed.

## Surface

- `index.ts`: service, schemas, queries, actions, `journalEntryLinkable`, DTOs.
- `ui.ts`: actions + types.
- Actions: reads on `authedAction` + `can(read, journal_entry)` (incl. `journalEntryHistoryAction`, F71); `createManualEntryAction`, `categoriseEntryAction`, `deleteManualEntryAction` on `ownerAction`.
- `links.ts` (T003): `linkEntry(tx, caller, audit, {id, to})` — a manual entry *Link to…* a document or a client invoice (`ENTRY_LINK_TARGETS`; supplier invoices and expenses write their own payments, D37). The allocation is proposed as the inbox does: min(what the entry has left, what the target has open) in the target's currency; a target with no amount is linked without one; another currency, a used-up entry or a bank entry refused. `linkEntryAction` on `ownerAction`.
- Linkable: manual entries carry `|amount|` and can be the source of a `justifies` link; bank entries are reached through their transaction — `exists` answers false for them, so `createLink` refuses a bank entry as an endpoint (T001: the same movement allocated twice otherwise).

- `history.ts` (F71): `entryHistory(tx, id)` — the panel's *History*, read from the audit trail (`journal_entry` rows), newest first: *Created* (import or *New entry*), then each update that changed an owner's fact (`changedFacts`: category, partner, note, *no document needed*) with *by a rule* when `categorised_by` became `rule`; an update that changed none of them (the retired implicit-rate write) is skipped. Nothing new stored.

## Page (part 2)

`/journal` — `ListPage` + `JournalTable` (DataTable on `JOURNAL_COLUMNS`: source, description, category, partner, amount in its currency, SEK base with the footer sum, flag, note; rate / rate source / bank rate / categorised-by hidden by default). The *Source* column and the panel's badge show the account's alias (*Nordea CHF*, T006; the filter stays Bank / Manual). **D40 kit (F71, `specs/journal/tasks.md` T011):** the title row's one primary is *New entry* (`NewEntryButton`); Date and Account are quick filters (`accountAlias` — a derived enum column, hidden by default, a manual entry under *Manual*); money through `formatMoney` (`data-amount` = the plain decimal; money in signed `+` in `text-state-done`), the *Source* and the BAS code as `<Tag>`s (`basName` drops the code from the label beside it), the counterparty key as a `<CodeChip>`; ⋮ row actions — a bank entry *Open the bank row* (`/banking?open=`), a manual entry *Delete entry* (owner, `ConfirmDialog`). The docked panel: title = date · amount · the Proof state, the account `<Tag>` and the description under it, then `DetailsSection`s **About** (SEK base, rate · rate source (· rate date when it differs), the bank rate of a paired leg (T007), counterparty, categorised by, created) · **Proof** (`EntryLinks`) · **Categorisation** (the form; the accountant sees a `DetailsGrid`) and *Delete entry* · **History** (collapsed, `EntryHistory`). A row opens the side panel with the `CategoriseForm` (category from the tenant's active BAS set — favourites first, `657 · Bankkostnader (alias)` — partner, note, *no document needed*; saved on change) a *Proof* section (`EntryLinks`, T003: a manual entry's links through `LinksList` with *Unlink*, and *Link to…* — search documents and invoices; a bank entry points to its bank row, `/banking?open=`) and, for manual entries, *Delete entry*. The *Proof* column (`linksState`, T004) shows the derived state with `<StateLabel>` (`state-family.ts`: none → attention, partly → in progress, justified → done, no document → neutral), filterable. *New entry* (`ManualEntryDialog`): date, description, signed amount, currency, optional typed rate, category, partner, note. `options.ts` (`categoryOptions`, `partnerOptions` — each partner with its `defaultBasCode`) feeds these lists server-side. Picking a partner on an entry with no category proposes the partner's default category (T002, `proposedCategory`): the categorise form saves it with the partner as the owner's choice (`categorised_by = manual`), the *New entry* dialog fills it and the owner can change it before saving; a category already set is never overwritten. `partner_default` stays the rule path's value. Nav: *Journal* for owner and accountant (reads). Strings `journal.*` en + fr + sv — every header and filter label from the dictionary (T009: `journal.col.created` / `updated` / `categoryCode` / `partnerId`, blanks through `common.blanks`; `journal-table.i18n.test.tsx`).
